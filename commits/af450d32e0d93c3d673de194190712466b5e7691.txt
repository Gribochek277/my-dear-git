Add the terminal dialog framework with clone, settings and theme dialogs
Dialog framework (src/tui/components/dialogs/): a declarative FormDialog on top
of the shell's DialogHost/TextPrompt primitives — text/toggle/choice fields,
Tab and Shift+Tab focus ring, per-field validation with the first invalid field
focused, Enter submit, single-shot Esc cancel, busy/inactive gating for nested
prompts, and a mouse region per field row and button.

Path prompt (src/tui/shim/dialog-service.ts + utils/path-input.ts): a queued,
promise-based prompt that serves the shim's native-dialog stand-ins
(app:open-repo-dialog, app:browse-directory, app:export-theme,
app:import-theme) with a live directory listing, ~ expansion, Tab completion
and validation; cli.tsx wires the adapters into bootstrap.

Core dialogs: CloneDialog (URL, target directory with completion and Browse…,
optional branch, live event:git-progress progress bar, failure message plus the
cleanup rule, activates the clone through the repo store), SettingsDialog
(theme preset, editor, git/ui toggles, maxRecentRepos, persisted through
useUiStore.saveSettings) and the theme import/export dialogs (export writes the
settings-file theme to a prompted path; import validates with parseThemeFile
and applies the tokens in one save).

DialogsLayer mounts all of it through App's decorations seam and owns two
provisional hotkeys (C clone, , settings); only the topmost dialog of the stack
is active, so settings -> theme export -> path prompt nests cleanly. The
sidebar's key handler now ignores keys while an input claim is active, matching
HistoryView, so a dialog or text field cannot leak keys into the pane behind it.
