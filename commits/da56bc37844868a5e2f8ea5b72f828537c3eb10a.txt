Stabilize branch-filter test and cap vitest workers
The branch-filter test clicked regions read straight after the first frame, so a busy machine could aim at an unmeasured 0x0 rect and then time out waiting for a fetch. It now waits for measured rects (waitForRegion), asserts the synchronously-set filter mode before waiting on the frame, and uses explicit 60s frame timeouts. vitest maxWorkers is capped at 4 so concurrent worker suites stop starving each other's git subprocesses. Two full runs and two focused runs are green.
